# 固定验证集调度优化目标可达性与实施方案

整理日期：2026 年 9 月 15 日  
适用项目：CPN HRL DAG  
适用范围：固定 validation 全量 108 场景，54 个基础 DAG，每个 DAG 对应同构与异构两种资源实现  
文档状态：下界与现状已经实测；后续算法路线为实施建议，尚未运行或承诺收益

## 一 核心结论

**在当前任务数据、资源配置、调度语义和 HEFT 分母均保持不变时，不能把这 108 场景的总 mean ratio 优化到 0.8。** 本次实际运行的数学下界审计已经排除该目标，并非仅凭搜索停滞作出的判断。

当前最好完整验证均值为 **0.918681240**。逐场景资源负载下界与乐观关键路径下界取最大值后，整体下界为 **0.894645343**。因此当前模型下，108 场景各自最优调度的平均比值满足：

```text
0.894645343 <= 理论最优平均比值 <= 0.918681240
```

这个区间不表示 0.894645343 一定可以达到。下界来自放松问题，忽略了部分约束，真正最优值可能明显高于下界。

更保守地说，**不使用关键路径推导，仅依赖资源负载的可行权重证书，均值下界已经是 0.818192464，仍然高于 0.8。** 联合下界进一步把 0.85、0.88、0.89 等总均值目标排除在外。

建议调整工作目标，而不是承诺不存在的优化空间：

1. 原主指标不变：以 **0.915、0.910** 为阶段验收门槛；将 **0.900** 作为高难度探索目标，而非承诺结果。
2. 原报告继续覆盖全部 108 场景：同时展示同构与异构分组，避免总均值掩盖结构差异。
3. 如果关心“0.8”这个数字，可另行讨论 **54 个异构场景的分组均值接近 0.8**。这是不同指标，不能冒充原 108 场景总均值；它也需要消除约 90.5% 的当前乐观剩余差距，难度很高。
4. 不再把主要预算用于扩大随机候选数量或缓存微调。优先投入**下界驱动的预算分配、多节点联合重分配、通信边界修复以及小窗口精确优化**。

本次没有训练新模型，没有运行 test，没有抽样 validation，也没有修改既有调度策略。新增的是只读可达性审计代码、测试与方案文档。

## 二 目标与当前差距

### 主指标必须固定

对场景 s，设当前调度 makespan 为 C_s，项目自有 HEFT 的 makespan 为 H_s：

```text
r_s = C_s / H_s
R = (1 / 108) × Σ_s r_s
```

R 是每个场景比值的算术平均，不是 mean(C_s) / mean(H_s)，不是仅异构子组均值，也不是优于 HEFT 的场景比例。

当前协议固定以下内容：

- manifest：`data/manifests/grapheonrl_mixed_iid_seed7.json`。
- 实验 seed：2026；manifest 名称中的 seed7 是划分标识，二者不能混淆。
- 场景总数：108；基础 DAG 数：54。
- 任务规模：50 任务 24 场景，100 任务 42 场景，300 任务 42 场景。
- 资源实现：同构 54 场景，异构 54 场景。
- 约束与执行路径：固定可行节点集合、执行时间模型、通信模型、依赖约束、节点非重叠和插入式调度。
- 基线分母：同一个场景、同一模拟器上的 canonical HEFT。

### 距离目标并非小幅调参

从 0.918681240 到 0.8，需要降低平均比值 **0.118681240**，相当于当前均值的约 **12.92%**；108 个场景的比值改善量之和需要达到 **12.817574**。

而目前审计出的乐观总空间只有：

```text
0.918681240 - 0.894645343 = 0.024035898
```

达到 0.8 所需改善是这个乐观空间的约 **4.94 倍**。即使假设每个场景都能达到当前下界，仍不能实现原目标。

| 分组 | 场景数 | 当前 mean ratio | 联合下界均值 | 乐观剩余均值空间 |
| --- | ---: | ---: | ---: | ---: |
| 全部场景 | 108 | 0.918681 | 0.894645 | 0.024036 |
| 同构资源 | 54 | 0.997162 | 0.993517 | 0.003646 |

同构组已经非常接近当前下界。其 ratio 接近 1，不能简单解释为算法没有学会优化；资源工作量约束已经限制了潜在收益。

同构与异构各占一半，因此：

```text
R = 0.5 × R_homogeneous + 0.5 × R_heterogeneous

如果同构组维持 0.997162420：
为了让 R = 0.8，异构组必须达到 0.602837580。

但异构组的联合下界已经为 0.795774115。
```

这也是原总均值目标不可达的直观解释。

## 三 下界审计及其可靠性

### 资源负载下界

设任务 i 在可行节点 j 上的运行时间为 p_ij，可行节点集合为 F_i。对于任意合法完整调度，节点 j 上所有任务的总运行时间 L_j 都不超过 makespan C，因为当前模拟器不允许同一节点上的任务重叠执行。

取任意满足以下条件的节点权重：

```text
w_j >= 0
Σ_j w_j <= 1
```

则有：

```text
LB_load(w) = Σ_i min_{j∈F_i}(w_j × p_ij)

LB_load(w)
<= Σ_i w_assignment(i) × p_i,assignment(i)
 = Σ_j w_j × L_j
<= C × Σ_j w_j
<= C
```

因此，任何满足非负与权重和约束的 w 都提供一个下界，不必相信某次 LP 返回的目标函数值就是最优解。

本次使用分数任务分配 LP 寻找较强权重：允许每个任务分散到多个可行节点，只约束每个节点的总负载，忽略依赖、通信以及任务不可拆分性。该放松问题由 SciPy 的 HiGHS 接口求解。代码取不等式对偶权重，截断微小负值并归一化，再根据上述公式重新计算下界，而不是直接把 LP 的 primal objective 当成证书。[R1]

**实测结论：108 场景的 load-bound ratio 均值为 0.818192464。** 即使不采用下一节关键路径下界，也已经排除总均值 0.8。

### 乐观关键路径下界

对每个任务 i 和其可行节点 j，定义忽略资源争用后的乐观最早完成时间 E_ij。按照 DAG 拓扑顺序计算：

```text
E_ij = p_ij + max_{u∈pred(i)} min_{k∈F_u}(E_uk + communication(u,i,k,j))

源任务的前驱最大值取 0。
不可行任务节点组合取正无穷。
LB_path = max_i min_{j∈F_i} E_ij
```

这个递推允许不同前驱各自选择最有利的节点，也忽略多个任务争用同一节点的情况，因而只会放松原问题。执行时间与通信时间均调用项目现有模型，不另建更有利的时间模型。

按拓扑顺序归纳可知，E_ij 不超过任何真实调度把任务 i 放到 j 时的完成时间，因此 LB_path 是下界。本次代码还用小型可穷举场景检验下界不超过实际最优调度。

### 为什么联合下界更高

每个场景先取两个下界的最大值，再求比值均值：

```text
LB_s = max(LB_load,s, LB_path,s)
R_lower = mean_s(LB_s / H_s)
```

不能把这个计算误写成 max(mean(load/H), mean(path/H))。有些场景受资源负载限制，另一些受依赖链限制，逐场景取最大值才能保留两类信息。

| 下界方法 | 全部场景平均比值 |
| --- | ---: |
| 仅乐观关键路径 | 0.590052 |
| 仅资源负载权重证书 | 0.818192 |
| 逐场景最大值组合 | 0.894645 |

### 数值处理与结论边界

- 108 组保存的节点权重均非负，权重和不超过 1。
- 联合下界整体乘以 1 − 1e-9 作保守数值收缩；每个场景都检查下界不高于当前已知可行解。
- 新增 5 项下界测试，包括小图穷举、独占资源瓶颈和强制跨节点通信；全仓库 **85 项测试通过**。
- 这不是形式化证明器输出的精确有理数证书。结论依赖已经核对的模型语义与浮点实现；但距离 0.8 的余量远大于所用数值容差。
- 若发现任务时长解析、节点可行性或模拟器语义本身有错误，应先修复并重新计算 HEFT、所有候选与下界。不能保留旧分母，只替换有利于候选的新模型。
- 若允许任务复制、抢占、任务拆分、并行扩展或者改变节点数量，当前下界的部分假设可能变化；这些属于新问题，不能直接沿用本报告的比较结果。

本次审计没有声称找到了每个场景的全局最优调度。下界是“不可能比它更好”的边界，不是“照着某个算法就能达到”的结果。

异构组当前为 0.840200，下界约为 0.795774。接近 0.8 在数值下界上尚未被排除，但需要消除约 **90.5%** 的乐观差距，不能当成轻松目标。

### 不能采用的达标方式

不能删除同构场景、只展示获胜场景、改变 50／100／300 场景权重、改成 makespan 总和之比、削弱 HEFT、关闭通信成本、忽略不可行调度，或者把搜索组合策略标成纯 RL 成果。

若业务确实要求不同资源设置或不同分布，应单独预先定义新协议，对全部方法重新评估，并与原 108 场景结果并列报告。不能为了得到 0.8 而事后挑选更有利的数据集。

## 五 用剩余空间决定优化方向

### 不再用 ratio 接近一作为唯一难度指标

对场景 s 定义：

```text
gap_s = max(0, C_s − LB_s) / H_s
```

gap_s 是当前解距离已知下界的乐观剩余空间。它比单独观察 r_s 更能帮助判断是否值得继续搜索。

本次审计发现：

- 33 个场景的 gap 不超过 0.001。
- 55 个场景的 gap 不超过 0.005。
- 68 个场景的 gap 不超过 0.010。
- gap 最大的 10 个场景约占全部乐观空间的 **43.7%**。
- gap 最大的 20 个场景约占全部乐观空间的 **69.6%**。

这些数字说明应采用统一的自适应策略，而不是把相同的大预算机械地分给所有场景。这里的“优先分析”不等于只验证这些场景；每次正式结果仍必须包含全部 108 场景。

### 优先诊断的例子

下表只用于定位算法缺陷，不应把场景 ID 写成运行时特殊规则。

| 场景 | 当前比值 | 下界比值 | 乐观空间 |
| --- | ---: | ---: | ---: |
| rnc50 rand0112 heterogeneous | 0.966554 | 0.807583 | 0.158971 |
| rnc300 rand0019 heterogeneous | 0.563780 | 0.427903 | 0.135877 |

第二个例子当前 ratio 已经很低，但仍可能有显著空间；这说明只追踪 ratio 最大的失败案例会遗漏机会。

### 每个场景应记录的诊断量

在固定验证运行中记录任务执行总量、节点忙时、关键路径时长、依赖通信等待、资源阻塞时长、可行节点数量、上下界差距，以及每个搜索算子的候选数、改善量和耗时。

算子评分使用改善量除以成本，例如累计 ratio 改善／累计真实模拟时间。若各约束的等待时间相互重叠，应避免把它们直接相加解释成 makespan 的可加分解。

## 六 算法路线

### 路线一 下界驱动的自适应预算

保留当前完整束搜索和关键块修复作为安全起点。根据新输入场景计算的 gap 分配后续预算，不依赖 validation 场景 ID，也不把本次审计排名作为查表策略。

建议先比较两条预先固定的预算规则，而不是大规模扫参：

- 小 gap：gap ≤ 0.001，保留当前解，不增加昂贵邻域。
- 中 gap：0.001 < gap ≤ 0.02，使用有限的联合重分配与顺序修复。
- 大 gap：gap > 0.02，允许小窗口精确优化或更长搜索。

上述阈值是首轮实验设置，不是已验证最优值。所有场景都需要得到合法输出和评估记录；“不追加搜索”不能表现为漏报样本。

终止条件使用剩余 gap、无改善次数和总时间预算。离线计算下界的耗时应单独报告；如果部署时每个新场景也要计算，就必须计入端到端延迟，不能仅用预缓存的 validation 下界计时。

预期作用是提高算力利用率，不是直接降低理论下界。这应当作为后续所有较强算子的控制层。

### 路线二 从同节点共置升级为多节点联合重分配

当前关键块修复把两到三个任务放到同一个节点，已经验证 mean ratio 从 0.919515 降至 0.918681。它没有覆盖以下重要邻域：

1. 两个任务交换所在节点。
2. 父任务与子任务分别迁移到不同节点，同时改善执行速度与通信路径。
3. 迁走瓶颈节点上的任务，并把其他节点上的任务补入，从而平衡资源负载。
4. 两到三个相互耦合任务分别选择不同的可行节点，而不是强制共置。

建议分两步实现：先加入双任务交换与双任务非共置；确认收益后再加入三任务联合重分配。对每个任务只保留至多三个候选节点，分别考虑执行速度、当前节点、通信邻近性和预计可用时间。

两任务的节点组合上限为 3²＝9，三任务为 3³＝27，再去掉原方案和非法组合。优先选取关键链、近关键链和共同资源瓶颈上的任务对，而不是枚举任意任务对。

每个联合赋值评估 preserve 与 greedy 两种修复。所有被联合指定的任务都必须服从指定节点，即使 greedy repair 已启动。完整候选仍由同一个模拟器评分，并保留原赢家。

建议第一轮每场景最多选 8 个任务对，每对最多 9 个组合，先设候选硬上限，再比较固定时间预算。节点排名是启发式，不应被当成可用于排除最优解的可靠下界。

### 路线三 修复通信边界和关键资源区段

仅移动关键任务本身，可能把跨节点通信转移到它的父任务或子任务上。下一类邻域应包含“边界任务”，例如关键父子边、fork 的多个子节点和 join 的多个父节点。

具体做法：

- 从通信等待或资源阻塞较大的关键事件出发，选择 3 至 6 个任务作为可调整窗口。
- 窗口应同时包含关键任务及一部分前驱、后继或同节点相邻阻塞者。
- 尝试多节点赋值、合法的任务顺序变化，以及小范围逐出再插入。
- 窗口外调度先冻结，或者只允许受影响的后缀重新调度，避免一次修改导致无法归因的大范围变化。
- 加入多条并列关键链与少量近关键链，防止只追踪当前单条关键链。

先加入与实际等待机制对应的有限算子，不要直接把窗口大小从 3 提高到 20。联合邻域的组合数很快增长，应以候选数和时间预算限制，而非只限制轮数。

### 路线四 小窗口精确优化

在剩余空间大、启发式多轮停滞的场景上，尝试用 CP SAT 或 MILP 求解一个有限的可调整子问题。外部研究已有把初始化、局部搜索和整数规划组合起来优化 DAG 调度的路线，但其 BSP 与 NUMA 模型不同，不能把论文改善比例直接当成本项目的预期收益。[R2]

首轮建议窗口 8 至 12 个任务，确认求解和回放接口后，再探索 16 至 24 个任务。每个任务保留少量可行节点，冻结窗口外任务或建立固定的边界约束。

子问题至少要表达：

- 每个任务恰好选择一个可行节点。
- 节点相关的执行时长。
- 同节点任务不可重叠。
- 前后依赖及节点相关的通信延迟。
- 窗口外前驱带来的释放时间。
- 窗口外后继和固定资源区段带来的边界约束。
- 原 incumbent 作为初始可行解或求解提示，且禁止返回比它更差的可部署结果。

Google 官方调度示例提供 precedence 与 no-overlap 建模基础，但它不是本项目异构 DAG 加通信约束的现成完整模型，不能只复制示例就认为约束已经一致。[R3]

**模型一致性是这一阶段最大的风险。** CP SAT 使用整数时间时，需要明确缩放与舍入方法。向上取整可用于保守构造候选，但其最优值不能直接当成原浮点问题的下界；向下取整的放松模型也只有在其他约束同样保持放松时才可用于下界。

求解器输出必须转换为项目支持的任务顺序与节点决策，再用当前模拟器完整回放。若求解器依赖模拟器不能表达的主动等待或其他语义，只能调整转换方式或拒绝该候选，不能直接把求解器 objective 填进报告。

局部子问题在冻结外部决策后得到的“最优”与“下界”，只对这个受限邻域成立。它不是整个 DAG 的全局最优性证明，也不能被用来排除所有其他调度。

建议求解失败、超时、无可行候选时立即回退 incumbent。正式比较依旧覆盖全部 108 场景，允许策略按统一 gap 规则为部分场景分配零额外求解时间。

### 路线五 多层粗化与展开

如果小窗口已经确认主要困难来自高通信耦合、而不是纯资源工作量，可以进一步研究多层方法：把强耦合任务暂时聚成超级节点，在较小图上选择资源分区，再展开并修复原任务调度。[R2]

粗化只能是搜索内部表示，不能改变最终任务清单、可行性或评价模型。强制共置可能丢失更好的解，因此保留未粗化的原搜索路径并取较优者。

由于现有共置块的收益较小，多层方法不应早于多节点联合赋值与小窗口精确优化。先证明问题确实来自跨边界耦合，再支付这一实现成本。

### 路线六 用学习压缩搜索成本

当前阶段不建议直接扩大 PPO 训练规模去追逐 0.8。学习模型也不能突破已经证明的可行调度下界。

只有当新搜索显著降低 ratio、但成本过高时，才考虑让模型预测候选排序、算子选择或潜在 regret，而不是直接替代全部约束与搜索过程。DAgger 可用于处理策略诱导的状态分布变化，但其通用结论不代表本项目一定获益。[R4]

这一阶段有明确权限和数据边界：

- 当前仍仅开展固定 validation 全量评估，不新增训练。
- 如果将来要训练，应先获得扩大工作范围的明确确认，再只使用独立 train DAG 生成训练状态和教师标签。
- 不能把本次 validation 上求出的优质轨迹、失败案例和 solver 标签用于训练后，继续称其为未见验证结果。
- 现有 smoke 配置中的小规模训练与六场景验证不能作为新的全量证据，不能直接沿用其选优结果宣称达到目标。
- 分别报告纯模型、搜索策略以及模型加安全搜索；不得把组合搜索收益归给纯 RL。

学习路线的主要目标应是恢复强搜索质量并降低耗时，而不是在缺乏可达空间时承诺进一步降低总均值。

## 七 实施顺序与验收门槛

以下时间和阶段划分是规划建议，不是已执行结果，也不保证每阶段都有效。

| 阶段 | 工作内容 | 必须交付 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| S0 | 下界与协议审计 | 108 场景下界 CSV 权重证书 与检查结果 | 本次已完成；独立复核后冻结审计口径 |
| S1 | gap 自适应预算 | 固定预算规则 分组成本和收益 | 合法性与基线保持不变；资源分配可解释 |
| S2 | 双任务多节点赋值 | 交换与非共置算子 完整消融 | 对原全量均值有实测改善，或同质量明显降时 |
| S3 | 三任务与边界修复 | 受限窗口算子 逐场景差异 | 相对 S2 有独立边际收益 |
| S4 | 小窗口精确优化 | 求解器与模拟器一致性测试 超时回退 | 额外收益值得计算成本，目标区间进一步收窄 |
| S5 | 多层或学习加速 | 仅在前置证据支持后立项 | 不破坏训练验证隔离；不掩盖组合方法成本 |

建议的第一轮具体工作包：

1. 冻结当前 blocks 配置和全部 108 场景报告作为 incumbent。
2. 新增一个双任务非共置算子，不同时修改 beam width、轮数、随机种子和多个评分权重。
3. 编写两任务交换才能改善、设备不兼容、通信方向非对称、回放与缓存一致等单元测试。
4. 新配置追加候选，不替换原路径；全量跑满 108 场景。
5. 按相同预算比较“新增算子”与“继续运行原算子”，避免把更多计算误认成算法优势。
6. 若双任务算子无明显收益，先检查高 gap 场景的失败机制，不继续机械地增加组合数量。

## 八 实验矩阵与预算

### 最小实验矩阵

不要做几十组参数的无约束搜索。建议预先限定以下对照：

| 编号 | 配置变化 | 对比目的 |
| --- | --- | --- |
| E0 | 当前 cached beam 加 blocks | 冻结质量基线 |
| E1 | E0 加 gap 自适应控制 | 判断预算分配是否有价值 |
| E2 | E1 加双任务交换与非共置 | 判断新邻域的独立作用 |
| E3 | E2 加三任务与通信边界 | 判断更大耦合窗口是否值得 |
| E4 | E3 加小窗口精确修复 | 估计更强搜索可获得的上界改进 |
| C1 | 原邻域使用与 E2 相当的额外预算 | 区分新算子与额外算力 |

每个配置都必须产生 108 条逐场景记录。场景顺序和数据一致；计时对照建议至少做 3 次交错顺序的完整运行，避免一直先跑旧版再跑新版。

### 计算预算的初步范围

当前 blocks 配置的历史平均推理时间约为 5.90 秒／场景；108 场景推理总量约 10.6 分钟，不含数据加载和报告生成。它是实测均值，不是每个场景的上限。

后续可以预设总预算档位，例如 10、30、120 秒／场景，分别对应最多约 18 分钟、54 分钟、3.6 小时的 108 场景推理预算。**这些只是预算换算，不是预计执行耗时，也不等于现有算法已经能满足该上限。**

若硬性保留完整旧搜索，而旧搜索单场景已经超过预算，则必须先调整预算定义或实现可中断的旧路径；不能既声称严格总时限又悄悄超时。报告要同时列出端到端时间、基线时间、新增搜索时间及求解器时间。

候选数预算和时间预算各有用途：候选数更容易确定性复现，时间预算更接近部署成本。首轮至少报告两者，而不是仅报告搜索轮数。

### 必须保存的指标

主表：mean ratio、95% 区间、max ratio、有效调度率、平均时间、P95 时间、峰值内存。

配对表：改善／退化／持平数量，使用明确的 ratio 容差 1e-9；记录每个场景的 delta ratio，而不是只比较两个总均值。

分组表：同构与异构、50／100／300 任务、gap 分位组。分组是完整结果的补充，不能替代主表。

诊断表：算子尝试次数、有效候选数、命中与去重数、solver 状态、额外耗时、改善量、上下界差距。

统计推断采用基础 DAG 为单位的配对 bootstrap，使同一个 DAG 的两种资源实现一起重采样。持续使用同一 validation 选择算法会造成选择偏差；区间只能作为探索性指标，不构成未触碰 test 上的泛化证明。

## 九 停止条件与风险控制

### 停止不可能目标

在当前协议下停止把“总均值 0.8”作为研发验收标准。更大的 beam、更深的 LNS、更强的神经网络和更长的 solver 时间都不能绕过下界。

### 停止低收益算子

建议预先设定以下决策规则，再进行实验：

- 同预算下，新算子两次完整对照仍无稳定收益，暂停扩展并回到诊断。
- ratio 改善小于 0.0005，却导致平均耗时增加超过 20%，默认不晋升为推荐配置；如业务明确愿意为质量付费，可单独保留质量档。
- 任一场景出现无效调度或违反保留 incumbent 的保证，先修正确性，不接受均值改善作为补偿。
- 某场景 gap 已低于预先规定的精度阈值，不再对它投入额外高成本搜索，但依旧完整评估和报告。
- solver 只证明某个冻结窗口不可改善时，停止该窗口，不把结论扩大为全局最优。

这些阈值是建议的工程决策标准，不是统计显著性定理，也不是已经执行的实验结果。

### 最大风险

| 风险 | 后果 | 控制措施 |
| --- | --- | --- |
| 把放松下界当成可达解 | 承诺无法实现的 0.895 或异构 0.8 | 始终同时报告上下界与实际解 |
| 求解器语义与模拟器不同 | 产生虚假的 makespan 改善 | 原模拟器回放作为唯一最终评分 |
| 只盯着 ratio 接近一的场景 | 把算力花在已接近最优的同构场景 | 使用 gap 和可解释瓶颈特征 |
| 在验证集上训练或记忆场景规则 | 破坏验证含义 | 不使用场景 ID 决策 不用 validation 标签训练 |
| 新增算子改变旧搜索路径 | 部分场景回归 | 先采用追加候选模式并保留原赢家 |
| 用更多算力冒充算法优势 | 质量收益与成本不可比 | 增加等时间或等候选数控制组 |
| 数值缩放忽略通信精度 | 约束被改变或下界失效 | 明确舍入方向与适用范围并复算 |

## 十三 最终建议

**先把目标从“固定总均值达到 0.8”纠正为“在下界约束内推进到 0.91 并探索 0.90”。** 这是基于完整 108 场景审计作出的目标校准，不是降低工作要求来掩盖算法不足。

下一步最值得实施的是 **gap 驱动预算加双任务多节点联合重分配**。它针对当前只做共置的邻域缺口，也能把计算预算放到确实还有空间的场景上。

如果用户特别关心异构资源能力，可把异构组 0.82、0.81、0.80 设为单独的挑战指标，同时保留原全部 108 场景主表。任何路线都必须由真实模拟器、固定协议和完整验证数据确认，不承诺下界以下的结果。
