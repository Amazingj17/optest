# Standard Task Graph (STG) Dataset with JSON Conversions for Workflow Scheduling in Heterogeneous HPC Systems

## Dataset Summary

This dataset extends the Standard Task Graph (STG) benchmark suite by providing benchmark-ready JSON workflow representations and system configurations for workflow scheduling research in homogeneous and heterogeneous HPC environments. The dataset is intended for optimization, heuristic, and learning-based scheduling methods.

## Supported Tasks

- Standard Task Graphs (STG)
- Workflow scheduling
- Heterogeneous HPC resource allocation
- Constraint-aware mapping and scheduling
- Benchmarking of optimization and ML schedulers
- Reproducible evaluation of scheduling policies

## Dataset Structure

The dataset contains three main components:

```text
original stg:
  Original Standard Task Graph files redistributed with permission

stg to json conversions:
  homo:
    rnc50
    rnc100
    ...
    rnc5000
  hetero:
    rnc50
    rnc100
    ...
    rnc5000

system_configs:
  homogeneous_nodes_scc_mb.json
  heterogeneous_nodes_scc_mb.json
```

Each graph family contains 180 variants.

## Data Instances

Each JSON workflow file contains:

- `meta`: provenance, STG source, graph statistics, mapping parameters, and system reference
- `tasks`: task-level workflow description

Each task entry contains:

- `cores`
- `memory_required`
- `features`
- `data`
- `duration`
- `dependencies`
- `tags`

## Example Task Record

## Source Data

The original graph corpus is based on the Standard Task Graph (STG) Set Project by Prof Dr. Hiroshi Kasahara and collaborators, Waseda University.

Original source:

- STG archive page: https://www.kasahara.cs.waseda.ac.jp/schedule/stgarc_e.html
- In particular, the dataset is derived from the random graph sets listed under "Standard Task Graphs (Version 2.0) Randomly Generated without Communication Costs".

The original STG files are redistributed with permission. The original dataset remains credited to the original authors.


## Conversion Methodology

The JSON workflows are generated by a dedicated conversion tool. The conversion pipeline performs the following steps:

1. Parse `.stg` task graph files and converts to `.json`
2. Extract task graph structure and metadata
3. Map STG processing time values to scheduling durations
4. Synthesize task resource requirements, including CPU cores and memory
5. Derive task data volumes
6. Generate homogeneous and heterogeneous workflow variants
7. Associate workflows with benchmark system configurations

For heterogeneous workflows, a configurable fraction of tasks may be assigned GPU requirements when the target system provides GPU-capable nodes.


## System Configurations

Two benchmark system models are included:

### 1. Homogeneous system

A homogeneous HPC cluster configuration with CPU-only nodes.

### 2. Heterogeneous system

A mixed environment including IoT, edge, cloud, CPU-only HPC nodes, and GPU-equipped HPC nodes.

These configurations describe:

- compute tiers
- number of cores
- memory capacity
- storage capacity
- supported processing features
- data transfer rates

## Intended Use

This dataset is intended for:

- academic research in workflow scheduling
- benchmarking of scheduling algorithms
- reproducibility of experimental evaluations
- training and evaluation of ML-based schedulers
- comparison of exact, heuristic, and learning-based scheduling methods

## Not Intended For

This dataset is not intended as a trace of real production HPC workloads. It is a benchmark-oriented real as well as synthetic workflow dataset derived from the STG corpus and enriched with scheduling-relevant metadata.

## Splits

The dataset itself does not impose train/validation/test splits. Users may define experimental splits according to their evaluation protocol.

## Limitations

- Resource requirements are synthesized from STG graph properties and mapping heuristics
- Durations are scaled for workflow scheduling experiments rather than representing measured runtime traces
- Heterogeneous feature assignment depends on conversion parameters and target system capability
