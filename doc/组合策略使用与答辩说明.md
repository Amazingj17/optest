# HRL＋独立 beam+blocks＋HEFT 组合策略

## 实现与定位

已实现 `IndependentHybridPolicy`，仍使用统一的 `SchedulerPolicy` 接口。
每个场景依次独立生成 HEFT、beam+blocks 和 HRL 完整调度，检查合法性，
选择 makespan 最小的方案，然后通过 ready/task/node mask 重放。

HRL 不参与 beam 搜索的初始候选或分支展开。搜索预算与原实验完全相同，
不受 HRL 输出影响。任何候选失败会明确报错，并清除上一场景的计划，
不会静默丢弃失败候选后继续宣称三路均完成。

候选生成和最终执行都使用同一个确定性离线模型。三个候选完整生成且合法时：

`C_hybrid = min(C_HEFT, C_search, C_HRL)`。

完全相等时按 HEFT、搜索、HRL 顺序择优。是否产生“严格改善”另外用
ratio 容差 `1e-9` 统计，不把数值扰动和并列选中解释为学习贡献。

这是组合策略的系统结果，不是纯 HRL 成绩。
既有 `hrl_safe` 与 `hrl_search_safe` 仍保持原实现；后者会把学习候选放入搜索候选池，
与本次独立生成后择优的方案不同。

## 本次完整验证结果

结果目录：`outputs/hrl_independent_hybrid_seed2026/`。
来源权重：`outputs/gpu/outputs/all_models_seed2026/training/residual_hrl/best.pt`，step=864。
搜索配置：`outputs/gpu/outputs/all_models_seed2026/configs/search.yaml`。
协议：seed2026、原 108 validation 场景／54 个基础 DAG、CPU 单线程。
本次不训练、不执行 test。

| 方法 | mean_ratio | 平均推理秒 | 合法率 |
| --- | ---: | ---: | ---: |
| HEFT | 1.000000000 | 0.2916 | 100% |
| 纯 HRL | 0.999530703 | 0.7644 | 100% |
| 独立 beam+blocks | 0.918681240 | 7.9259 | 100% |
| 三路组合 | **0.918677321** | **9.6993** | **100%** |

组合相对 HEFT 的平均 ratio 降低约 **8.1323%**；106 个场景改善，2 个持平，0 个退化。
相对纯搜索：2 个场景严格改善，106 个持平，0 个退化；平均 ratio 仅再降低 **0.000003920**。
按 54 个基础 DAG 分组 bootstrap 的组合减搜索差值 95% CI 为 `[-0.000009878, 0]`。
不能据此宣称 HRL 带来稳定且显著的额外优势。

最终选中搜索 103 次、HEFT 2 次、HRL 3 次。其中 HRL 的 1 次选中差值约
`9.97e-10`，低于严格改善阈值，因此只计 2 次严格改善。

| HRL 严格改善的场景 | 搜索 ratio | HRL／组合 ratio | ratio 降低 |
| --- | ---: | ---: | ---: |
| `rnc100:rand0024:homogeneous` | 约 0.989468 | 约 0.989247 | 约 0.000220206 |
| `rnc100:rand0178:homogeneous` | 约 1.000000 | 约 0.999797 | 约 0.000203122 |

本次三路独立候选的逐场景 ratio 与原六方法实验中对应 HEFT／HRL／搜索的 108 条记录一致。
时间来自本次 Windows 机器进程内测量，不与 GPU 服务器旧耗时直接比较。
单分支计时范围与 Evaluator 相同，包含 policy.reset 和完整调度执行；组合计时额外包含
三路环境初始化、校验、选择及最终重放。没有通过缓存历史结果或忽略分支耗时压低组合时间。

去 HRL 的结果是 `min(HEFT, search)`，mean_ratio=0.918681240；
去搜索的结果是 `min(HEFT, HRL)`，mean_ratio=0.993455994。
后者不是包含扰动候选的旧 HRL-safe。去分支消融只重用独立候选计算 makespan，
没有将分支时间相加冒充这两种子集策略的独立端到端实测。

## 使用

从项目根目录执行：

```shell
python scripts/evaluate_independent_hybrid.py --config configs/hrl_independent_hybrid_seed2026.yaml --output outputs/hrl_independent_hybrid_rerun
```

输出目录须为空或不存在。配置只有权重路径、搜索配置路径、validation split 和输出目录；
环境、数据与归一化协议来自权重配置，并校验搜索配置与其一致。
改变机器路径时保持数据划分、数据内容和搜索参数不变。

主要代码：

- `src/cpn_hrl_dag/policies/hybrid.py`：组合策略、独立候选生成与合法重放。
- `scripts/evaluate_independent_hybrid.py`：正式全量验证、来源记录、收益归因和报告。
- `configs/hrl_independent_hybrid_seed2026.yaml`：当前运行配置。
- `tests/test_independent_hybrid.py`：搜索独立性、择优保证、异常与接口校验、108 场景夹具流程。

主要产物：

- `RESULTS.md`、`comparison.csv`：总体效果与耗时。
- `candidate_audit.csv/jsonl`：每个场景三路候选分数、耗时、选中来源。
- `candidate_schedules.jsonl`：324 条候选调度的任务—节点序列，可用于案例复核。
- `attribution.json`、`paired_statistics.json`：去分支消融、改善次数与基础 DAG 分组置信区间。
- `provenance.json`、配置副本与 `split_manifest.json`：checkpoint 哈希、运行环境与协议。
- `events.jsonl`、`status.json`：增量进度与完成状态。

相关测试：

```shell
python -m pytest tests/test_independent_hybrid.py tests/test_advanced_search.py -q
```

本轮组合、搜索和既有训练路径共 **97 项回归测试通过**，日志为结果目录中的
`pytest_results.txt`。`verification.json` 记录了 432 条评估记录、324 条候选调度、
逐场景择优保证、原 checkpoint 哈希未变化，以及三路候选与原六方法实验一致的核对结果。

## 答辩建议

可以直接说：

> 我们完成了可训练的两层 HRL 调度框架，并采用独立搜索和 HEFT 候选增强最终调度。
> 三路候选在统一模型下生成、校验并择优。在固定 108 场景中，组合平均 ratio 为 0.918677，
> 相比 HEFT 平均降低约 8.13%，调度合法率 100%。
> 当前主要收益来自搜索，HRL 在两个场景提供了很小的额外改善，因此我们分别报告纯 HRL、
> 纯搜索和组合结果，不将全部收益归因于强化学习。

若被问到“为什么还用 HRL”，说明它是框架中已经训练和验证的策略模块，当前额外性能贡献有限；
下一步才是用训练集搜索轨迹指导 HRL，以减少在线搜索成本。不要把尚未完成的教师训练当作现有成果。

本次是在 Windows 上验证组合功能；国产操作系统实测与交付证据仍需单独完成。
