## 一、结论先行

1. **目前已有完整验证证据的最佳方案是 HEFT-safe 搜索加关键块联合迁移**，固定 108 场景 validation 的 mean ratio 为 **0.918681240**，108/108 调度合法，最大 ratio 为 1.0。
2. 从最初的 HEFT-safe portfolio 的 **0.957167660** 降至 **0.918681240**，平均比值降低 **0.038486420**，相对该初始均值下降约 **4.02%**。相对 HEFT，平均归一化 makespan 改善约 **8.13%**。
3. 当前主要收益来自**候选构造、局部搜索、多起点 beam 和关键块联合迁移**；缓存与去重主要降低计算开销。不能把这些结果归功于新加入的 Graph PPO 或 Tier MAPPO。
4. **当前固定任务下，总体 mean ratio=0.8 不可达。** 本地审计给出的联合下界均值为 **0.894645343**；仅资源负载下界均值也达到 **0.818192464**。这些是下界，不是已经找到或保证能够达到的调度成绩。
5. **新两种学习基线已落实代码，正式对比尚未完成。** 首次 GPU 训练异常中断；两种方法已统一改用 CPU 从头执行相同预算。快照时 Graph PPO 完成 322/2592 个训练场景，Tier MAPPO 尚未开始。
6. 当前可以确认搜索优化取得进展，但**还不能给出两种新学习方法的性能排名，也不能声称任一方法已经达到 0.8**。

这里的“改善约 8.13%”指逐场景归一化改善的平均值，不是所有场景 makespan 求和后的整体缩短比例。

## 二、统一指标与实验边界

### 2.1 主指标

对场景 s，令 C_s 为当前策略 makespan，H_s 为同一场景、同一模拟器下的 canonical HEFT makespan：

```text
ratio_s = C_s / H_s
mean_ratio = (1 / 108) × Σ ratio_s
```

- 越低越好；HEFT 自比值为 1。
- 使用“逐场景比值的均值”，不是 mean(C_s) / mean(H_s)。
- 调度合法性是硬要求，均值改善不能补偿无效调度。
- 改善、退化、持平比较使用 ratio 容差 1e-9。
- HEFT-safe 搜索保留 HEFT 候选，因此可以保证不劣于 HEFT；纯学习基线没有此保证，ratio 大于 1 必须如实报告。

### 3.1 哪些改动带来了质量改善

- **从单一扰动扩展为多类候选。** 加入 PEFT/OCT 前瞻、通信权重变化和有限偏差候选，使用同一个模拟器评估完整调度并择优，始终保留 canonical HEFT。
- **关键链局部修复。** 同时考虑依赖约束和同节点资源阻塞形成的实际关键链，尝试节点迁移、保留后缀或贪心修复后缀，再扩展任务次序相关邻域。
- **多起点 beam。** 不局限于单个当前赢家，保留不同候选继续扩展，三轮版本改善到 0.919514912。它是 archive-based 多起点变体，不保证逐场景优于旧 wide-LNS 路径。
- **关键块联合迁移。** 从单任务移动扩展到实际关键链上 2～3 个任务的联合同节点放置，降低部分场景中耦合通信或资源阻塞的影响。

Beam 不是越复杂就自动越好：一轮版本 S7 的总体 ratio 比 S6 更差、耗时更高；三轮版本 S8 才得到更低总体 ratio。即便 S8 的均值更好，与 wide-LNS 的逐场景比较仍有 3 个场景退化，因此必须保留配对分析。

### 3.2 哪些改动主要改善速度

前缀缓存复用候选重放中的公共调度前缀。S8 到 S9 的 mean ratio 保持一致，历史平均耗时从 8.2532 秒降到 5.8035 秒，约下降 **29.68%**。S10 的归档均值同样保持 0.919514912。

这是工程计算效率改进，不是新的调度质量突破。历史硬件负载、实现版本和计时环境可能不同，不应仅凭小幅耗时差异宣称确定的算法加速；特别是 S9 与 S10 的差异，需要交错重复测量才能稳健判断。

## 五、为什么不能把总体 0.8 作为当前验收目标

已完成只读下界审计，未改变任务约束或 HEFT 分母：

| 审计项 | 108 场景的平均归一化下界 |
| --- | ---: |
| 资源负载下界 | 0.818192464 |
| 乐观关键路径下界 | 0.590051812 |
| 每场景取两类下界最大值后的联合下界 | 0.894645343 |

联合下界是先对每个场景取较强下界，再计算均值，不是简单取两列整体均值的最大值。

```text
当前最好均值：          0.918681240
联合下界均值：          0.894645343
乐观剩余空间：          0.024035898

到 0.8 所需降低：       0.118681240
所需降低 / 乐观空间：   约 4.94 倍
```

在当前数据、合法调度定义、计算/通信模型与分母都不变的前提下，任何合法算法都不能把总体均值降到 0.8。扩大 beam、延长训练或换网络结构不能突破这个限制。

同时也不能承诺达到 0.894645343：下界来自放松问题，未必存在一个合法完整调度能达到它。合理方向是缩小已知上下界差距，并同时控制耗时；若另设新任务或改变数据协议，必须作为新实验，不能与当前 108 场景成绩混报。

详细推导和后续搜索方案见 [validation_target_080_plan_zh.md](../docs/validation_target_080_plan_zh.md)。

## 六、学习方法的实现与训练状态

### 6.1 需要区分的三条学习路线

| 路线 | 已有事实 | 当前能否作为新两方法排名证据 |
| --- | --- | --- |
| 历史 Residual HRL / HRL-safe | 已有历史训练和完整验证结果，HRL-safe 包含安全搜索组合 | 不能；不是本次两个新基线 |
| 图策略模仿/蒸馏探索 | 早期小规模 smoke 暴露训练损失下降但策略表现退化的分布偏移问题 | 不能；不是固定 108 场景的新正式对比 |
| Graph PPO 与 Tier MAPPO | 已实现共同数据协议、训练、checkpoint、全量评估与可视化 | 等待两种方法完成后判断 |

早期 smoke 的经验仅提示“训练损失下降不等于调度性能提高”，不把其子集数字用于本次正式成绩，也不建议重新启用抽样 validation。

### 6.2 两种新基线

| 项目 | Graph PPO | Tier MAPPO |
| --- | --- | --- |
| 代码标识 | `graph_ppo` | `tier_mappo` |
| Actor | 一个 Actor 对合法任务—资源对建模 | 端、边、云三个 Actor 分别提出动作 |
| 执行动作 | 全局合法动作对中选择 | 学习型协调器选一个层级提案执行 |
| Critic | 中央状态 Critic | 中央团队 Critic |
| 编码器 | 任务图 + 资源图 | 相同骨干配置；多个 Actor 共享编码器 |
| 当前默认参数量 | 31,518 | 58,979 |
| 搜索/HEFT residual/安全兜底 | 无 | 无 |

两者仍共同使用环境提供的 HEFT 相关特征和归一化尺度。“纯策略”表示不把搜索赢家或安全兜底拼接进结果，并不表示完全不使用启发式特征。

Tier MAPPO 是项目适配版，有中央协调器，不是严格分散执行，也不宣称逐项复现未完整提供的论文或原项目。

### 6.3 匹配的训练预算

- seed=2026，每种方法 **3 个 epoch**。
- 每个 epoch 全量遍历 **864 个 train 场景**，打乱顺序但不放回。
- 每种方法计划训练 **2592 个场景次数**；这些不是 2592 个互不重复的新场景。
- 每轮使用完整 **108 个 validation 场景**选优，训练结束重载 best checkpoint 再验证。
- 两种方法完成后，在相同 CPU 评估后端进行统一配对比较；不运行 test。
- 两者匹配训练场景、骨干配置和超参数预算，但不等参数量，也不保证实际耗时相同。

## 九、下一步安排与验收标准

以下是后续建议，不是已经实现的新结果；本次总结没有启动额外搜索或改动正在运行的训练。

### 优先级 1：先完成当前对比闭环

1. 等待两种方法按相同预算训练完成，保留所有成功/失败记录。
2. 用固定 108 场景统一重评 best checkpoint，报告 mean/max ratio、合法率、平均/P95 耗时和端边云分配。
3. 按基础 DAG 成组做配对统计，明确差值为 MAPPO−PPO，负数才代表 MAPPO 更好。
4. 如果学习策略比 HEFT 或搜索差，照实保留结果，不临时增加兜底后仍称为同一纯学习方法。
5. 单 seed 结果只支持初步描述，不能宣称跨随机种子稳健；本次不擅自追加多个 seed 的训练成本。

### 优先级 2：搜索优化围绕真实 gap，而不是盲目追 0.8

- 以当前最好解与下界之差分配额外搜索预算，优先关注异构资源和耦合较强的场景；不减少完整 validation 覆盖。
- 研究多节点联合重分配、通信边界修复和小窗口精确修复，突破当前“少数关键任务同节点放置”的邻域限制。
- 新算子采用追加候选、保留原赢家的方式接入，并用同预算旧算子对照区分算子收益与额外算力。
- 耗时对照做完整场景的重复交错测量，不能用不同机器负载下的一次计时宣布微小加速。

### 最低验收要求

| 维度 | 要求 |
| --- | --- |
| 数据 | 固定 manifest，完整 108 场景；不改分母，不抽样 |
| 合法性 | 108/108 合法 |
| 质量 | 保存逐场景结果、均值、最差值、改善/退化/持平数量 |
| 安全搜索 | 保留 incumbent 的改动应满足逐场景不退化 |
| 纯学习 | 允许劣于 HEFT，但不得隐藏或替换失败场景 |
| 成本 | 记录实际训练预算、完整调度耗时和参数量 |
| 统计 | 配对分析以基础 DAG 为组；明确 validation 选择偏差 |
| 状态 | 区分已完成、失败、运行中和仅有方案；不填补不存在的成绩 |
