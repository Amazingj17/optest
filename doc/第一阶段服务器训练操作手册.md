## 0. 先决定训练什么

| 场景 | 用什么 | 是否需要 GPU 长训练 |
| --- | --- | --- |
| 只想定位退化来源（**推荐**） | 从已有主模型第一轮 checkpoint 分叉，跑两个 1728-episode 分支 | 需要，约 2 × 6 小时量级（见 §7） |
| 已经没有任何主模型 checkpoint | 先用正式配置从零训练主模型，再分叉 | 需要，约 18 小时量级 + 分叉 |
| 只想先确认代码能跑 | `configs/stage1_smoke_phases.yaml`（8 episode） | 不需要，CPU 即可 |

**必须先确认的来源 checkpoint 事实**（本轮已核实）：

```
outputs/gpu/outputs/all_models_seed2026/training/residual_hrl/
  best.pt     global_step=864   ← 第一轮 high_train 结束、被选为最佳的 checkpoint（正确来源）
  latest.pt   global_step=2592  ← 三轮训练全部结束的最终模型（错误来源）
```

两者 `best_validation_ratio` 都是 `0.9995307`，光看这一列**无法区分**。只能看步数或权重：

| 文件 | global_step | high actor | low actor 输出层 |
| --- | ---: | --- | --- |
| `best.pt` | 864 | 已训练（128 个非零权重） | **仍然全零**（低层从未训练） |
| `latest.pt` | 2592 | 已训练 | 已训练（joint 阶段更新过） |

从 `latest.pt` 分叉会得到「已经联合训练过的模型」，不再是「第一轮之后的分叉」。**用 `best.pt`。**


预检依次检查 6 项，任何一项不通过就直接退出，**不会启动训练**：

2. 输出目录不存在或为空（非空则拒绝；请选择新目录）；

5. **跑一个真实 probe episode**：确认 CUDA 可用、掩码与冻结/活动接线正确，
   `high_loss=None`（冻结）或 `low_loss=None` 与阶段一致；

## 5. 正式启动两个分支

两个分支各自 1728 episode、各自 2 个完整覆盖轮；可以**一张卡顺序跑**，也可以**两张卡各跑一个**。
先确认你被授权使用的 GPU 编号，不要占用看似空闲的其他卡。

```bash
cd /data/jyq/optest
mkdir -p logs
SRC=outputs/gpu/outputs/all_models_seed2026/training/residual_hrl/best.pt
```

**方案一：一张卡顺序跑（GPU 1）**

```bash
CUDA_VISIBLE_DEVICES=1 nohup python -u scripts/train_main_comparison.py \
  --config outputs/stage1_forks_seed2026/configs/high_only_eft.yaml \
  --fork-from "$SRC" \
  > logs/stage1_high_only_eft.log 2>&1 &
echo $! > logs/stage1_high_only_eft.pid

CUDA_VISIBLE_DEVICES=1 nohup python -u scripts/train_main_comparison.py \
  --config outputs/stage1_forks_seed2026/configs/low_only_frozen_high.yaml \
  --fork-from "$SRC" \
  > logs/stage1_low_only_frozen_high.log 2>&1 &
echo $! > logs/stage1_low_only_frozen_high.pid
```

**方案二：两张卡并行（GPU 1 和 GPU 2）**

```bash
CUDA_VISIBLE_DEVICES=1 nohup python -u scripts/train_main_comparison.py \
  --config outputs/stage1_forks_seed2026/configs/high_only_eft.yaml --fork-from "$SRC" \
  > logs/stage1_high_only_eft.log 2>&1 &
echo $! > logs/stage1_high_only_eft.pid

CUDA_VISIBLE_DEVICES=2 nohup python -u scripts/train_main_comparison.py \
  --config outputs/stage1_forks_seed2026/configs/low_only_frozen_high.yaml --fork-from "$SRC" \
  > logs/stage1_low_only_frozen_high.log 2>&1 &
echo $! > logs/stage1_low_only_frozen_high.pid
```

注意：

- 两个分支的 `output_dir` 不同，互不覆盖；配置里的 `device: cuda` 会使用 `CUDA_VISIBLE_DEVICES` 选出的那**一张**卡。
- 脚本会拒绝写入非空目录，所以**不要**为了重跑而复用同一个目录名（用 `stage1_forks_seed2026_r2` 之类）。
- 没有 `--resume`，本阶段也**不宣称**精确断点续训；中断后用新目录重跑，保留旧目录作证据。
- Slurm 环境先 `srun`/`sbatch` 申请资源，再在作业脚本里执行上面命令；不要清空调度器给的 `CUDA_VISIBLE_DEVICES`。

## 7. 时间与资源预算

正式主模型 2592 episode 用了约 22574 秒（episode 采集 + PPO 更新，单卡）。

| 分支 | episode | 覆盖轮 | optimizer 更新 | 粗估（按主模型同尺度） |
| --- | ---: | ---: | --- | ---: |
| A `high_only_eft` | 1728 | 2 | high 1728 / low 0 | 约 6–7 小时（低层不更新，可能略快） |
| B `low_only_frozen_high` | 1728 | 2 | high 0 / low 1728 | 约 6–7 小时（高层冻结，可能略快） |

这只用于预留作业时限，**不是承诺**：真实耗时取决于 GPU、CPU 线程数、并发任务与场景规模分布。

以及结束时的一次全量验证。

磁盘：每个分支约与主模型同量级（checkpoint 2 MB 级 + `events.jsonl` + 诊断 JSONL 约 20–30 MB 每千 episode + 验证产物）；
先 `df -h .` 确认空间。

## 8. 两个分支完成后怎么比较

阶段一的比较基准是**纯 HRL 的 mean_ratio**，不是 loss：

```bash
cd /data/jyq/optest
for BRANCH in high_only_eft low_only_frozen_high; do
  echo "== $BRANCH =="
  python - <<PY
import json
d = json.load(open('outputs/stage1_forks_seed2026/$BRANCH/summary.json'))
print({k: d.get(k) for k in ['mean_ratio','std_ratio','max_ratio','num_scenarios','num_base_dags',
                             'valid_schedule_rate','selected_step','training_episodes',
                             'optimizer_updates_high','optimizer_updates_low','diagnostics_enabled']})
PY
done
```

也把来源 checkpoint（step 864）在同样 108 场景上的基线纳进来作为参照：该值就是
`0.9995307034820944`（来源目录 `validation_history.json` 的 epoch 1 记录），
以及步数路径：

| 点 | episode | 108 场景 mean_ratio |
| --- | ---: | ---: |
| 初始（残差为零） | 0 | 0.99990793 |
| 第一轮结束（= 分叉点，`best.pt`） | 864 | 0.99953070 |
| 第二轮结束 | 1728 | 1.00401581 |
| 第三轮结束（`latest.pt`） | 2592 | 1.01173057 |

报告时必须写清：

- 两个分支与正式主模型是**不同实验**，分别是「第一轮之后继续高层训练」与「第一轮之后只训低层」；
- 两分支**episode／环境决策预算相同，optimizer 更新次数不同**（1728 次，但作用在不同网络）；
- 单 seed（2026），不给跨 seed 稳健性结论；
- 本阶段**不宣称**必然缩短 makespan，也不因 loss 下降就认定调度改善；
- 正式验收看 mean_ratio、与来源 checkpoint 的配对差值、退化场景数量与分组结果、合法率、推理时间。

## 10. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `REFUSING: output directory is not empty` | 目录名复用了。换新目录名；预检不提供删除目录功能 |
| `REFUSING: evaluation.proxy_scenarios must be 0` | 配置不是由 `prepare_stage1_forks.py` 生成的（基础模板里是 18）。重新生成 |
| `fork source checkpoint config hash mismatch` | `best.pt` 被改动过，或用错了文件 |
| `scheduling environment differs` / `model configuration differs` | 分叉配置的 model／environment／reward 与来源 checkpoint 不一致；用生成的配置，不要手改这几段 |
| `comparison uses normalized observations and the unchanged default environment` | 配置里 `environment` 多了键；生成的配置只保留 `normalize_observations: true` |
| `ValueError: unknown hierarchical training phase` | 阶段名拼错。允许：`high_only_eft`、`low_only_frozen_high`、`joint`、`low_pretrain`（`high_train` 等价于 `high_only_eft`） |
| 想要「无高层预训练」或「无 HEFT 残差」消融 | `run_ablations.py` 现在会**拒绝** `no_staged` 与 `no_heft_features`，因为它们的旧实现并不具备名字对应的语义。等第二／三阶段给出正确实现后再做 |
| 训练中途被打断 | 没有 `--resume`；`latest.pt` 只保证模型/优化器可加载，RNG 与采样器游标不恢复。保留目录，用新目录重跑 |
