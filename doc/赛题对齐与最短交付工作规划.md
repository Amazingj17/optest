# 赛题对齐与最短交付工作规划

## 1. 决策摘要

**先补国产操作系统实测与工程闭环，再完成三种神经模型训练、六种策略比较；按剩余时间追加种子或单项消融。暂不增加数据规模。**

目标是最短时间内交付符合赛题、可以一键复现、有可信结果的完整框架，不是训练尽可能多的探索模型。本文是计划，日志、覆盖采样、统一流水线等改造尚不代表已完成。

依据：[赛题要求](赛题要求.md)、[历史比较结果](主模型与基线统一对比结果_2026-09-20.md)、[服务器使用手册](Linux_GPU服务器部署与扩训完整使用手册.md)。

### 国产系统先确认

普通 Linux GPU 服务器不自动满足 openEuler/openKylin/OpenHarmony 等要求。若 GPU 服务器不是要求中的系统，可在另一个实际国产系统环境完成开发调试、测试、短训练和原全量 108 验证，GPU 服务器完成长训练，两套证据分开。容器／虚拟机是否满足“基于该系统开发”需向主办方确认；README 声明或镜像名不是实测证据。不擅自重装共享服务器。

## 3. 最小完整实验

数据保持原训练集 432 个基础 DAG／864 场景，规模 50/100/300；validation 始终原 54 DAG／108 场景。禁用 proxy，不评估 test，不更改分母或重划验证。资源配置替换能力用训练来源样例或单元测试夹具展示，不形成额外正式验证集。

| 方法 | 是否单独训练 | 定位 |
| --- | --- | --- |
| Residual HRL | 是 | 主模型 |
| Graph PPO | 是 | 学习基线 |
| Tier MAPPO | 是 | 学习基线，说明为项目适配实现 |
| HRL-safe | 否 | 复用本轮主模型权重，加安全候选选择 |
| HEFT | 否 | 启发式参照 |
| beam + blocks | 否 | 独立搜索，不含神经候选，披露额外耗时 |

“所有模型”指当前正式比较模型。Flat PPO、联合图策略、蒸馏、DAgger 等探索入口不进入紧迫交付关键路径，未完成实验不冒充正式成果。

### 核心预算与公平性

建议先 seed=2026，三模型各训练 3 个完整覆盖轮次，即各 2592 episodes。主模型第 1 轮高层训练、第 2–3 轮联合训练；每轮全部 864 场景无放回打乱，尽量使用可追踪的一致顺序。这是预算建议，不是收敛保证。

当前主模型是有放回采样，完整覆盖需先实现。相同覆盖／episode／任务决策，不等于相同参数量、优化器更新次数或算力；报告称“匹配训练场景覆盖”，不能称完全等计算预算。第一轮不同时探索复杂课程。

初始、每轮结束、最终选中 checkpoint 均验证全部 108 场景，三模型使用统一节奏与预先确定的选模规则。固定预算核心实验完成全部轮次，早停另做配置；故障／超时未完成标记 partial，不混入 completed。

### 有余量时

优先补三模型的 seed=2027、2028，共增加 6 次训练，形成每模型 3 seed。另一选择是同预算的一项消融：去 HEFT 残差，或去高层预训练。单 seed 消融仅作探索证据。预算只够主模型补 seed 时，不能称所有方法均完成多种子比较。选择在看结果前按时间和论证需求决定。

旧 run_ablations.py 的 no_staged 只迁移 low_pretrain_episodes，未处理 high_train_episodes；no_heft_features 不等于关闭高低层残差。正式消融前修正语义并加测试，不能直接用旧入口凑图。

## 4. 工程优先级

### P0：长训练之前

1. 国产系统证据、服务器依赖和 GPU 检查。
2. 实时 flush 日志与增量 JSONL／CSV，训练和全量验证均输出进度。
3. 独立目录禁止覆盖；原子 checkpoint；失败状态和 traceback。
4. 一键预检→三模型训练→六策略评估→绘图→动态报告；失败不能假报成功。
5. 主模型覆盖采样、统一场景／episode／任务决策计数。
6. 动态读取实际训练预算、seed、最佳 step/epoch，去除写死历史信息。

当前恢复不完整。若服务器作业时限足够，最小版本可先采用整阶段重跑并保留失败产物；若作业时限不足，随机状态、采样器、优化器、调度器、历史日志完整恢复必须升为 P0，不宣传未经验证的精确续训。

日志字段至少包括：时间、模型、seed、阶段、epoch、episode/总数、scenario_id、任务数、累计决策、覆盖量、reward、loss、KL、学习率、耗时、验证均值和历史最佳。验证至少每 10 场景输出 completed/108；搜索等长步骤标注当前场景。ETA 只是估计。

### P1：训练时同时做

架构与动作图、数据隔离图、赛题对齐表、动态图表模板、国产系统功能测试、依赖记录、复现说明、汇报提纲。用历史真实结果开发图表，不伪造新训练曲线。

### P2：余量工作

多种子、单项消融、剖析后的吞吐优化、大图扩容。不优先增加新模型、开发 DDP 或更换训练框架。

## 5. 最短时间安排

硬件和截止时间未知，不能承诺训练小时数。先测量再定预算：

1. 系统／依赖／数据／GPU／测试；每模型少量训练加全量 108 验证。短跑仅验功能和估时，不作为正式成绩。
2. 完成 P0，并测试异常、日志落盘、目录保护、完整验证，再启动长训练。
3. 单 GPU 默认顺序训练；多 GPU 可一卡一模型，目录及 CPU／内存隔离。不默认同卡并发三个重任务。
4. 训练期间整理材料和图表模板，不等训练结束才准备汇报。
5. 统一硬件和线程评估六策略，核验 648 条逐场景结果，出图、报告和演示。

估时公式：初始化／加载＋episodes×平均训练耗时＋完整验证次数×108场景验证耗时＋最终评估／出图。训练按规模分布加权，冷启动影响单列。建议保留约 20%–30% 交付窗口用于重跑、核验与材料整理，这不是性能预测。

如果预算不足，在正式实验开始前统一减少三模型覆盖轮数或删除可选实验；不偷偷缩短某个模型，不以 partial 冒充完整结果。历史结果独立标注并保留作备份。

## 7. 成果与目标表述

赛题是 DRL 框架，主叙事必须是主模型与统一框架，不能用搜索成绩代替神经模型。历史 HRL／HRL-safe／搜索均值约 0.995168／0.953510／0.918681，不是本轮扩训成绩。

已有[固定验证下界审计](../docs/validation_target_080_plan_zh.md)：原数据、资源、语义和 HEFT 分母不变时，联合下界约 0.894645，已排除总体 mean_ratio=0.8。不再以 0.8 为短期交付承诺。

新训练可能不改善，须如实披露，不把旧模型冒充新产物。train/validation DAG 隔离支持未见图验证，但 validation 参与选模，不能称独立 test 泛化。工作量用模块、测试、真实日志和可复现产物证明，不堆砌未完成模型名。

README／docs/reproduction.md 仍含旧 proxy 和 test 示例，正式交付前标为历史或更新。generated_smoke.yaml 使用子集和新资源，不能当作固定 108 正式验收命令。

建议 10–12 页：问题与赛题→框架→数据和协议→模型与合法动作→训练日志→总体结果→分组和耗时→案例→国产系统与复现→总结局限。已完成多种子／消融可增加一页或放附录。

## 9. 启动前确认

- GPU 型号、数量、显存，CPU 与内存。
- 实际操作系统，是否有可用国产系统环境。
- 最迟交付／汇报时间，是否 Slurm，作业时限。

这些信息决定并行度、覆盖轮数和恢复优先级，不改变原固定 108 验证。确认前可推进日志、流水线和测试，不承诺服务器完成时间。
