# 主模型架构与流程

> 本文介绍当前项目的主方案：`CPN-HRL-DAG` 残差分层强化学习策略，以及部署时使用的 `HEFTSafePortfolioPolicy` 安全搜索层。  
> 它们共同构成“学习决策 + 可验证候选搜索”的主系统；Graph PPO 与 Tier MAPPO 是后续对比基线，不是本文的主体。  
> 说明依据当前代码实现和归档配置，重点解释数据如何流动、每个模块做什么、训练与部署为何不同。

## 1. 先区分三个运行形态

主系统不是把一个神经网络直接输出最终排程，而是分为三个清晰的形态：

| 形态 | 对应实现 | 作用 | 是否保证不差于 HEFT |
| --- | --- | --- | --- |
| 纯学习策略 | `CPNHRLDAGPolicy` | LSTM 选任务、GAT 选资源，逐步构造一个排程 | 否 |
| HEFT-safe 组合 | `HEFTSafePortfolioPolicy` | 生成并模拟多个完整候选，选 makespan 最小者 | 是 |
| HRL-safe 部署方案 | `HEFTSafePortfolioPolicy(learned_policy=CPNHRLDAGPolicy)` | 将纯学习排程作为一个候选加入安全搜索 | 是 |

因此：

- **Residual HRL** 是可单独评估的学习模型，用于观察神经策略本身的贡献。
- **HEFT-safe 搜索** 是不依赖神经网络也可运行的安全优化器。
- **HRL-safe** 是实际部署层：它不相信学习模型一定更好，而是让学习模型与 HEFT、扰动启发式和局部搜索候选进行同一模拟器下的公平比较。

下面的主路径可概括为：

```text
GrapheonRL DAG + 云/边/端资源
          │
          ▼
Scenario 预处理（拓扑、依赖、资源、带宽、执行时间）
          │
          ▼
ScheduleSimulator ──► CloudEdgeEndDAGEnv
          │                       │
          │                       ├── 高层观测：所有任务的状态 + 全局资源状态
          │                       └── 低层观测：已选任务在每个节点上的 EST/EFT 等
          ▼
Residual HRL：LSTM 选 ready task → GAT 选 feasible node
          │
          ▼
逐步提交到同一模拟器，得到完整 schedule
          │
          ├── 纯策略模式：直接报告该 schedule
          │
          └── HRL-safe 模式：与 HEFT / 搜索候选一起比较，回放最优 schedule
```

## 2. 统一调度环境：所有模块共享同一语义

### 2.1 输入对象

一个 `Scenario` 包含：

- DAG 任务及依赖边；边携带数据量。
- 云、边、端计算节点及其计算速度、CPU/GPU/内存能力、设备特征。
- 节点间带宽矩阵及可选时延矩阵。
- 任务资源需求或设备约束。

场景预处理缓存任务拓扑序、前驱/后继列表、入/出度、拓扑层级、边数据矩阵及任务—节点执行时间矩阵。策略网络不负责重建这些结构。

### 2.2 调度动作与约束

每一步是一个层次动作：

```text
高层动作 a_high：从 ready tasks 中选择任务 i
低层动作 a_low ：为任务 i 从永久可行节点中选择节点 j
```

任务可选当且仅当全部前驱已被放置；节点可选当且仅当其永久满足该任务的资源/设备约束。**节点忙碌不会被掩掉**：忙碌会改变开始时间和 EFT，而不是让该节点从动作空间消失。这一点使策略能在“等待当前快节点”与“立即转移到慢节点”之间学习取舍。

`ScheduleSimulator` 对动作做最终验证，并以插入式列表调度计算：

```text
dependency_ready(i, j)
  = max_{p ∈ predecessors(i)} [finish(p) + comm(p, i, node(p), j)]

EST(i, j) = 当前节点时间线中不早于 dependency_ready 的最早空闲槽起点
EFT(i, j) = EST(i, j) + execution_time(i, j)
```

它保证：每个任务只调度一次、任务时长正确、依赖通信约束成立、同一节点时间线不重叠。所有策略（HEFT、学习策略、搜索候选）都经由这个模拟器评分，因此比较不会因不同执行语义而失真。

## 3. 观测与特征流

环境在每个决策点提供两级观测。配置中启用 `normalize_observations: true` 时，大部分时间量按当前场景的 HEFT makespan 归一化，从而减少 50、100、300 任务规模之间的数值尺度差异。

### 3.1 高层：任务选择观测

高层输入包含形状为 `[任务数, 17]` 的任务特征和形状为 `[节点数, 5]` 的资源特征。

任务特征主要由以下信息构成：

| 类别 | 特征 |
| --- | --- |
| 任务结构 | 工作量、入度、出度、拓扑层级、源/汇标记 |
| 调度进度 | 已调度标记、ready 标记、已完成前驱比例、全局进度 |
| 成本摘要 | 各节点执行时间的均值、最小值、最大值；入/出数据量 |
| 启发式信息 | 归一化 HEFT upward rank 及其尺度 |

资源特征为计算速度、当前时间线最晚结束时间、已分配任务数、CPU 容量、内存容量。它们使高层不仅能看 DAG 重要性，也能感知整个资源系统的当前负载。

高层的 `ready_mask` 在 PPO 分布与确定性推理中同时使用；非 ready 任务的 logit 会被屏蔽，不能被采样或选中。

### 3.2 低层：资源选择观测

选定任务 `i` 后，低层看到该任务自身的高层特征、资源网络图与每个节点的任务条件特征 `[节点数, 8]`：

```text
compute_speed,
execution_time(i, j),
communication_time(i, j),
dependency_ready_time(i, j),
EST(i, j),
EFT(i, j),
available_at(j),
assigned_task_count(j)
```

资源图的邻接关系来自正带宽连接；边特征为归一化带宽和时延。低层 `node_mask` 只保留对任务 `i` 永久可行的节点。

### 3.3 HEFT 信息的角色

主模型使用 HEFT 信息作为**状态特征与策略先验**，不是把 HEFT 的最终答案直接写入网络输出：

- 高层以 upward rank 表示“任务优先级”。
- 低层以 EFT 表示“当前任务放到某节点后的局部完成时间”。
- 环境用 HEFT makespan 做奖励与时间特征的归一化尺度。

这三类信息均由当前场景和当前部分排程计算，不读取 validation 结果、未来排程或其它策略的最终成绩。

## 4. Residual HRL：两级 Actor-Critic

### 4.1 高层网络：任务选择 LSTM

实现类为 `HighLevelLSTMActorCritic`。其计算过程是：

```text
任务特征 [B, T, 17]
  → Linear(17, 128) + tanh
  → LSTM(128, 128)
  ├─ Actor：Linear(128, 1) → 每个任务一个残差分数
  └─ Critic：masked task pooling + mean resource pooling
             → Linear(128 + 5, 128) + tanh → Linear(128, 1)
```

LSTM 按稳定拓扑任务顺序处理任务序列，因此能在逐任务表示中编码局部上下文。它不是按时间步保存跨调度决策的隐藏状态；每次前向都会用当前完整任务特征序列重新计算序列表示。

高层输出每个任务的 actor logit 与当前状态价值 `V_high(s)`。只有 `ready_mask=True` 的任务可参与 categorical 分布。

### 4.2 低层网络：资源选择 Dense GAT

实现类为 `LowLevelGATActorCritic`。其计算过程是：

```text
节点条件特征 [B, N, 8]
  → DenseGATLayer(8, 64, 4 heads)
  → ELU
  → DenseGATLayer(64, 64, 1 head)
  = 节点表示 h_j

已选任务特征 [B, 17]
  → Linear(17, 64) + tanh
  = 任务表示 q_i

[h_j, q_i, 节点条件特征去除 speed 后的 7 维 timing]
  → Linear(64×2 + 7, 64) + tanh → Linear(64, 1)
  = 节点 j 的残差分数
```

每个 GAT 层以多头注意力聚合资源图邻居。注意力得分同时含节点表示、带宽/时延边特征，并通过资源图邻接掩码限制传播范围。低层 Critic 将节点表示均值和当前任务特征拼接，输出 `V_low(s, i)`。

### 4.3 HEFT 残差化：从可靠先验出发

当前主配置开启 `heuristic_residual`，所以网络并非从随机策略开始。最终 logit 为：

```text
high_logit(i) = 8.0 × normalized_upward_rank(i)
                + 0.5 × tanh(neural_high_residual(i))

low_logit(j | i) = -8.0 × normalized_EFT(i, j)
                  + 0.5 × tanh(neural_low_residual(i, j))
```

Actor 输出头最后一层在初始化时置零，因此开始训练时：

- 高层确定性选择具有最高 upward rank 的 ready task；并以任务 ID 稳定打破并列。
- 低层确定性选择具有最小 EFT 的可行节点；并以节点序号稳定打破并列。

策略包装器对“残差输出头仍全零”的 checkpoint 还保留 float64 的精确 HEFT 排序快速路径，避免 float32 网络 logit 在极小并列差异上改变 HEFT 次序。

残差使用 `tanh` 限制在 `[-0.5, 0.5]`，而启发式权重为 8。这使训练初期的策略变化是受限的局部偏移，不必先重新学会 HEFT；同时也意味着在该配置下，单步残差不能轻易颠覆差距较大的 HEFT 排序。训练获得稳定性，但会限制探索幅度，这是有意的设计取舍。

## 5. 训练流程：分阶段 Masked PPO

### 5.1 奖励

提交任务—节点动作后，环境产生：

```text
r_t = - (partial_makespan_t - partial_makespan_{t-1}) / HEFT_makespan
```

当前主配置令通信附加奖励权重为 0，也没有启用 potential shaping。`gamma_high = gamma_low = 1.0` 时，一条完整轨迹奖励之和等于最终 makespan/HEFT 比值的负数：

```text
Σ r_t = - final_makespan / HEFT_makespan
```

这让训练优化信号和评价的归一化目标对齐；模型选择仍然只看完整 validation 的 mean ratio。

### 5.2 三个训练阶段

| 阶段 | 高层任务决策 | 低层节点决策 | 更新哪个 PPO Agent |
| --- | --- | --- | --- |
| `low_pretrain` | 固定 HEFT upward-rank 任务 | 低层策略采样 | 仅低层 |
| `high_train` | 高层策略采样 | 固定最小 EFT 节点 | 仅高层 |
| `joint` | 高层策略采样 | 低层策略采样 | 两者都更新 |

正式 `zenodo_heft_safe_fast_2026` 配置使用 0 个 low pretrain、75 个 high train、75 个 joint episode。前 75 步仅训练任务选择器，节点放置固定为最小 EFT；后 75 步共同优化。训练采样遵循课程：先在 50～100 任务场景上训练 75 步，再扩展到 50～300 任务场景。

### 5.3 PPO 更新细节

每个层级各自保存以下 rollout 项：观测、当时动作 mask、采样动作、旧 log-prob、Critic value、reward、done。更新时必须使用原 mask 重建 categorical 分布，避免已经不合法的动作重新进入概率空间。

对每个层级的 GAE：

```text
δ_t = r_t + γ V(s_{t+1}) (1 - done_t) - V(s_t)
A_t = δ_t + γ λ (1 - done_t) A_{t+1}
R_t = A_t + V(s_t)
```

策略目标是标准 PPO 截断替代项，叠加 value 损失并减去熵奖励：

```text
L = -min(ρ_t A_t, clip(ρ_t, 1-ε, 1+ε) A_t)
    + c_v × value_loss
    - c_e × entropy
```

当前主配置的核心稳定参数为：`clip_coef=0.1`、`target_kl=0.01`、value clip `0.2`、梯度范数上限 `0.5`、每次 rollout 最多 2 个 PPO update epoch、学习率线性衰减至初值的 0.2。若近似 KL 超过 `1.5 × target_kl`，该次更新提前停止。

不同规模 DAG 的 rollout 形状不同。实现先按 tensor 形状分组，再对每组执行批量 LSTM/GAT 前向；这提升效率，但不会改变每条记录自己的历史 mask。

### 5.4 验证与 checkpoint 选择

训练脚本会在 step 0 先验证 HEFT 等价的初始化策略，并保存 `best.pt`。之后每 25 个 episode 先检查固定、按任务规模平衡的 18 场景 proxy；只有 proxy 改善才运行完整 validation，并以完整 validation 的 mean ratio 决定是否更新 best checkpoint。

这是一种减少完整验证开销的训练控制机制。最终模型仍应通过完整固定 validation 报告；proxy 不应被当作最终成绩。早停耐心值为 4 次未改善检查。

## 6. 部署层：HEFT-safe 搜索组合

### 6.1 为什么部署层还需要搜索

纯神经策略可能在局部状态中做出不可逆且较差的选择。安全层不修改环境约束，而是对多个完整候选使用同一 `ScheduleSimulator` 重放和测量，再选择实际 makespan 最小者。它不是对神经网络 logit 做后处理，也不是只比较局部 EFT。

`reset(scenario)` 时就完成候选计划；随后 `select_task` 和 `select_node` 只按顺序回放获胜候选的 `(task, node)` 决策。因此外部 Evaluator 仍走统一两级策略接口。

### 6.2 候选生成层次

当前最佳搜索配置 `zenodo_heft_safe_search_beam3_r3_blocks_2026.yaml` 的候选流程如下：

```text
候选 0：canonical HEFT（始终存在）
  │
  ├─ PEFT/OCT：lookahead weight = 0.0, 0.25
  ├─ Scaled HEFT：通信缩放 = 0.0, 0.25, 2.0, 4.0
  ├─ 有限差异：1 个节点层面的低 regret 偏差候选
  ├─ 16 个确定性 seeded top-k HEFT 扰动候选
  └─ 可选：Residual HRL 完整 rollout（仅 HRL-safe 模式）
          │
          ▼
      选当前 incumbent
          │
          ▼
三轮 beam 局部搜索（宽度 3）
  ├─ 沿实际关键链尝试节点迁移
  ├─ 尝试邻近关键链任务次序变动
  └─ 保留原后缀或用贪心 EFT 修复后缀
          │
          ▼
最多两轮关键块优化
  └─ 从实际关键链选 2～3 个任务，求公共可行节点，尝试联合放置
          │
          ▼
同一模拟器选 makespan 最小候选，回放其完整决策序列
```

所有候选都保留决策顺序和节点放置。候选完全调度后才被比较，不以启发式分数替代最终评价。

### 6.3 HEFT 安全性为何成立

安全性来自具体实现约束：

1. canonical HEFT 永远是第一个候选。
2. 每个候选先经过同一模拟器得到完整、合法的 `SimulationResult`。
3. 候选以 `(makespan, 生成顺序)` 取最小；相同 makespan 时 HEFT 优先。
4. 最后显式断言所选 makespan 不大于 HEFT makespan 加数值容差 1e-9。

所以 HEFT-safe 或 HRL-safe 的 `max_ratio <= 1` 是设计不变量。该保证只适用于安全组合层，不适用于单独的 Residual HRL。

### 6.4 搜索加速与边界

局部搜索通过 `ScheduleSimulator.clone()` 分支部分排程；前缀缓存复用同一 incumbent 的公共调度前缀，避免每个候选从任务 0 重放。结果缓存可选，当前最佳配置保留前缀缓存。

关键链由最终 makespan 任务反向追踪，候选原因同时包括：依赖到达时间和同节点上最后一个阻塞任务。因此它不是只看 DAG 的静态最长路径，而是反映已实现排程中的通信与资源竞争瓶颈。

当前关键块算子只尝试短块的共同节点放置；它不等价于全局最优求解，也尚未覆盖任意多节点交换、任意任务重排或精确全局求解。

## 7. 训练态、推理态和部署态的数据流

```text
训练（stochastic）
Scenario → Env observation → High PPO sample task → Low PPO sample node
         → Simulator step/reward → high/low buffers → GAE + PPO update

纯策略推理（deterministic）
Scenario → Env observation → High argmax over ready mask → Low argmax over feasible mask
         → Simulator step → final schedule

HRL-safe 部署（deterministic planning）
Scenario → HEFT / 搜索 / 可选 HRL rollout 分别生成完整 schedule
         → Simulator measured makespan 比较 → 保存赢家 decision sequence
         → 标准策略接口回放赢家 schedule
```

三种模式使用同一场景、执行时间模型、通信模型、合法性定义和 `ScheduleSimulator`。区别仅在于动作是采样、直接选择，还是先规划后回放。

## 8. 当前配置的结构参数与责任边界

### 8.1 Residual HRL 主配置

| 模块 | 当前设置 | 含义 |
| --- | --- | --- |
| 高层 | hidden=128，LSTM 开启 | 输出每个任务的分数和状态价值 |
| 低层 | hidden=64，GAT 第一层 4 heads | 输出每个节点的分数和任务条件价值 |
| 残差先验 | weight=8.0，limit=0.5 | 以 HEFT rank / 负 EFT 为主，网络做有界偏移 |
| 优化器 | Adam | 高层 lr=1e-4，低层 lr=5e-5 |
| PPO | γ=1，λ=0.95，clip=0.1 | 目标与终局 makespan ratio 对齐 |
| 观测 | HEFT 归一化开启 | 降低任务规模间的数值漂移 |

### 8.2 需要避免的误解

- LSTM 是对任务特征序列建模，不是跨整个 episode 维护在线记忆。
- GAT 只在资源网络上做消息传递；任务 DAG 的结构信息在高层特征中通过度、层级、数据量和 HEFT rank 显式提供。
- HEFT-safe 不是 actor 网络的一层，而是独立候选规划与模拟选择器。
- HRL-safe 的改进不能全部归因于神经网络，因为其结果还受搜索候选影响；应同时报告 pure HRL 与 safe 组合。
- 纯策略允许比 HEFT 差；安全组合保证不差于 HEFT，但要付出候选构建与完整模拟的推理成本。
- 当前模型是离线 DAG list scheduling，不是在线到达任务的连续资源调度器。
